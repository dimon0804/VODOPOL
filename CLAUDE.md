# Водополь — правила работы над проектом

«Водополь» — устаревшее и областное русское слово для половодья, разлива.
Технический пакет и каталог репозитория остаются `floodvalue`: менять их на середине
работы дороже, чем польза от совпадения имён.

КосмоХакатон 2026, кейс 2: «ИИ-оценка экономического ущерба от паводка и оптимизация
заказа ДЗЗ». Команда CLV-DIGITAL.

По одному чипу Sentinel-1 из официального Sen1Floods11 определяем воду двумя методами,
считаем ожидаемый прямой ущерб десяти условных объектов, сами нарезаем зоны
дополнительной съёмки, считаем их цену по ПП РФ № 840 и сравниваем стратегии A/B/C
при объявленном бюджете. Всё это показываем оператору и выкладываем воспроизводимо.

Полный разбор кейса, критерии, план и решения — в вольте:
`../FloodVault/` (вход — `_CONTEXT.md`).

## Что уже проверено и не требует перепроверки

- Бакет `sen1floods11` публичный по HTTPS, `gsutil` не нужен:
  `https://storage.googleapis.com/sen1floods11/v1.1/<path>`.
- Размеченная часть: 446 чипов, 11 событий. Нужны слои `S1Hand`, `LabelHand`,
  `JRCWaterHand`, `S1OtsuLabelHand` — это около 0,5 ГБ, а не 14 ГБ из README.
- `S1Hand`: 2 канала VV/VH в дБ, float32, nodata = NaN, EPSG:4326, шаг 9e-05°.
- `LabelHand`: −1 нет метки, 0 не вода, 1 вода. `JRCWaterHand`: 0/1, постоянная вода.
- Сетки слоёв одного чипа совпадают — перепроецировать для совмещения не нужно.
- Авторский split режет чипы случайно внутри одних и тех же 10 событий: это утечка,
  мы делаем свой сплит по событиям, Bolivia отводим под проверку переноса.
- Формула цены ПП 840 в `contracts.py` сверена с контрольным примером постановки:
  1 703,46 / 946,37 / 567,82.

## Правила, нарушение которых стоит баллов

1. **Test открывается один раз.** Порог, калибровка и конфигурация выбираются только
   на validation. Посмотрели на тест и что-то подкрутили — это новый эксперимент.
2. **Целевой класс — временное затопление**, а не вода вообще:
   `LabelHand == 1 AND JRCWaterHand == 0`. Подпись результата должна соответствовать.
3. **EL = p × V × q считается по вероятностному растру, независимо от маски.**
   Низкое p не обнуляет ущерб и не исключает объект из расчёта.
4. **Для `partial` и `no_data` поля p/EL/rank пустые, а не нулевые.** Ни в одном
   CSV/JSON/GeoJSON пакета не должно быть NaN и Inf.
5. **Зона заказа** — один полигон без внутренних вырезов, площадь ≥ 1 км² **до**
   округления, оплачивается по контуру. Площадь считается через EPSG:6933.
6. **Скидка Р пересчитывается для корзины целиком** при любом изменении состава.
   Складывать однажды посчитанные цены одиночных зон нельзя.
7. **`base_rate_status = scenario`** держим везде, пока нет проверяемого источника
   действующей ставки БРЕ.
8. **Смена бюджета не переобучает модель** и не меняет пороги — пересчитываются
   только отбор зон, цены и сравнение стратегий.
9. Каждый эксперимент, включая отклонённые гипотезы, — строка в
   `../FloodVault/02_Состояние/Журнал_экспериментов.md`.

## Команды

```bash
python -m src.cli.fetch_data          # выгрузка слоёв из официального бакета
python -m src.cli.make_splits         # сплит по событиям
python -m src.cli.train_baseline      # пороговый baseline
python -m src.cli.train_main          # основной метод
python -m src.cli.infer --chip <id>   # inference на произвольном официальном чипе
python -m src.cli.run_bundle --chip <id> --budget <rub>   # весь пакет одного запуска
python -m src.validate_bundle outputs/<run_id>            # проверка пакета
```
