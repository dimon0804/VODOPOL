# Никите: зона сервиса

Проект называется **«Водополь»** — старое слово для половодья. Это имя на панели,
в отчёте и на защите; каталог и пакет в коде остаются `floodvalue`.

КосмоХакатон 2026, кейс 2 «ИИ-оценка экономического ущерба от паводка и оптимизация
заказа ДЗЗ». Делим как на прошлом хакатоне: я — модель и экономика, ты — сервис.

## Что делает продукт

По радарному снимку Sentinel-1 считаем вероятность затопления, переводим её в
ожидаемый ущерб по десяти объектам, сами нарезаем зоны дополнительной съёмки, считаем
их цену по ПП РФ № 840 и сравниваем три стратегии закупки при заданном бюджете.
Оператор видит это на одном экране и может менять бюджет.

## Точка стыка — `src/runtime.py`

Ты не считаешь ничего сам. Все расчёты я отдаю через один модуль:

```python
from src.runtime import RunContext

ctx = RunContext.load("outputs/<run_id>")   # готовый комплект одного запуска

ctx.summary()                # чип, событие, дата, порог, бюджет, статусы, версии
ctx.assets()                 # GeoJSON десяти объектов с p, EL, uncertainty, rank, status
ctx.candidates()             # каталог зон: геометрия, цена, срок, параметры заказа
ctx.strategies(budget_rub)   # A/B/C под заданный бюджет — пересчёт без переобучения
ctx.sensitivity()            # таблица чувствительности
ctx.raster_png(kind)         # ("s1" | "probability" | "mask" | "uncertainty") -> (png_bytes, bounds)
ctx.bundle_zip()             # весь комплект файлов одним архивом
```

Всё возвращает обычные словари, списки и байты — сериализуй как есть.
Я даю тебе этот модуль с заглушками сегодня, наполняю по ходу; сигнатуры не меняются.

## Что нужно сделать

### 1. `src/api/` — FastAPI

Эндпоинты один в один под методы `RunContext`:

| Метод | Путь | Отдаёт |
| --- | --- | --- |
| GET | `/api/health` | состояние сервиса, версия, загруженный run_id |
| GET | `/api/run` | `ctx.summary()` |
| GET | `/api/assets` | `ctx.assets()` |
| GET | `/api/candidates` | `ctx.candidates()` |
| GET | `/api/strategies?budget=250000` | `ctx.strategies(budget)` |
| GET | `/api/sensitivity` | `ctx.sensitivity()` |
| GET | `/api/raster/{kind}.png` | PNG + заголовок с границами для наложения на карту |
| GET | `/api/bundle.zip` | архив комплекта |

Требования: CORS для локальной разработки, аккуратные ошибки (понятный текст, а не
трейсбек), отсутствующий комплект — это 404 с объяснением, а не падение.
Никаких вычислений в слое API.

### 2. `web/` — панель оператора

Обычный Leaflet, без сборщиков и фреймворков, если не хочется иначе. На одном экране:

- **карта**: подложка S1, поверх — слой вероятности с легендой, переключатель на
  бинарную маску и на слой неопределённости;
- **десять объектов** точками: цвет по рангу ущерба, подпись с типом, p, ущербом и
  статусом; рядом таблица, отсортированная по ожидаемому ущербу;
- **зоны съёмки**: весь каталог светлым контуром, выбранные в текущей стратегии —
  заливкой; при клике карточка с ценой, площадью, сроком и параметрами заказа;
- **слайдер бюджета** — главный интерактив. Двигаем → перезапрашиваем `/api/strategies`
  → перерисовываются выбранные зоны и таблица A/B/C. Подпиши явно: модель не
  переобучается, пороги не меняются;
- **таблица A/B/C**: стоимость данных, прочие затраты, полная стоимость, бюджет,
  уложились или нет, уникально покрытый ущерб, доля покрытия, остаточная
  неопределённость со статусом;
- **кнопка выгрузки** комплекта.

Жёсткое требование кейса: рядом с каждым числом видно, **сценарное оно или измеренное**.
У стратегии B, если она вышла за бюджет, — явная пометка «контрфактическая».
Ставка съёмки у нас сценарная, это должно быть написано на экране, а не спрятано.

Ролевые профили пользователей делать **не надо** — организаторы на сессии прямо
сказали не заигрываться. Один пользователь, один процесс, доведённый до конца.

### 3. Docker и запуск

`Dockerfile` + `docker-compose.yml`, чтобы поднималось одной командой:
`docker compose up --build` → интерфейс на `http://localhost:8000`.
Веса модели и комплект запуска монтируются, а не пересобираются.
Исходный набор Sen1Floods11 в образ не кладём — он качается отдельной командой.

### 4. `README.md`

Титульный файл для жюри. Обязательно: ссылка на официальный Sen1Floods11, точный
commit, версии зависимостей, инструкция получения данных и команды для подготовки
выборки, обучения обоих методов, независимой проверки, inference **на другом
официальном чипе**, расчёта ущерба и A/B/C, пересчёта бюджета, запуска интерфейса и
выгрузки комплекта. Плюс таблица «где что искать по критериям оценки» — как в фенологе,
она тогда хорошо зашла.

## Чего делать нельзя

- Считать что-либо в обход `src/runtime.py` — иначе цифры на экране разойдутся с файлами.
- Класть датасет или чужие данные с ограничениями в репозиторий.
- Показывать сценарные числа как подтверждённые.
- Пересчитывать что-то при смене бюджета, кроме отбора зон, стоимости и сравнения.
